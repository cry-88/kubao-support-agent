# 阶段 5 · 管理看板升级（数据分析可视化）

> 目标：在原有看板上补齐趋势图、意图饼图、坐席绩效、知识缺口四块分析视图。
> 硬约束：**只追加 DOM 与渲染逻辑**，原有统计卡片与 `renderStats` 一行未改；`admin.js` 零改动。

---

## 一、前后端分工

```
admin.html      追加 4 个容器（#csChartTrend / #csChartIntent / #csAgentPerf / #csGapTop）
assets/dashboard.js   新增：取数 + 渲染 + 触发调度（独立 IIFE，不依赖 admin.js 内部状态）
assets/admin.css      追加 .cs-* 样式，不复用也不覆盖原有类
server/analytics      新增 dashboard()：一次算齐四块
server/rpc.js         新增 cs_admin_dashboard（管理员口令）
```

为什么把四块合成一个接口：看板每次刷新要四份数据，拆成四次 RPC 会吃四份额度，而且可能出现"趋势是这一秒、坐席是下一秒"的口径漂移。现在是**同一个数据快照 + 一次限流计数**。

---

## 二、四块视图与口径

| 板块 | 指标来源 | 窗口 | 展示形式 |
| --- | --- | --- | --- |
| 工单量趋势 | `ticket_trend` | 14 天（可配） | 三条折线：新建 / 转人工 / 已解决，带网格、Y 轴刻度、悬停数值 |
| 意图标签占比 | `intent_share` | 同趋势窗口 | 环形图 + 图例（数量 / 百分比），圆心显示总单量 |
| 坐席绩效 | `agent_workload` | 近 30 天（不足 30 天按 30 算） | 表格：接单量、已解决、解决率（条形）、平均首响、评价数、好评率（条形） |
| 知识缺口 Top 5 | `knowledge_gaps` | 近 30 天 | 排序列表：次数徽标 + 原始提问 + 意图 + 最近出现时间，附"去知识缺口页"跳转 |

口径全部复用阶段 2 的只读执行器，没有为看板另写一套算法——**同一个词只有一种算法**，这是刻意的。

坐席与缺口用 30 天窗口的原因：14 天里经常只有一两个工单落进来，首响/解决率没有统计意义；趋势和意图则要"近两周"的短期视角。

## 三、前端实现要点

### 3.1 不侵入 admin.js

`admin.js` 是 IIFE，没有对外暴露登录/切页事件。为了不改它，`dashboard.js` 用两条信号判断"该渲染了"：

1. `MutationObserver` 观察 `#console` 与 `#tab-overview` 的 `class` 变化（登录会移除 `hidden`，切页会切换 `hidden`）；
2. 30 秒定时器兜底刷新（仅在概览页可见时发请求）。

口令从 `sessionStorage['cs_admin_code_v1']` 读取——即 `admin.js` 登录后写入的那一份，没有第二套凭证。

### 3.2 图表用原生 SVG

没有引入 Chart.js / ECharts：

- 项目定位是零依赖、离线可跑，Pages 静态托管也不该多拉一个 200KB 的包；
- 需求只要求四张固定图表，用 `<svg>` + `polyline`/`circle` 足够；
- 悬停提示用原生 `<title>`，不写自定义 tooltip 层。

折线图 14 天 × 3 条线 = 42 个数据点，环形图每段一个 `circle` + `stroke-dasharray`，都是几十行代码。

### 3.3 权限与降级

| 场景 | 行为 |
| --- | --- |
| 管理员登录 | 正常渲染；顶部提示"14 天窗口…" |
| 坐席口令登录 | 后端返回 `unauthorized`，`dashboard.js` 把整块 `.cs-dashboard` 隐藏，不弹错、不刷屏 |
| 接口异常（非权限） | 各卡片显示"看板加载失败：<原因>"，保留页面可用 |
| 无数据 | 各卡片显示空态文案（如"暂无意图数据"），不是空白或 `NaN` |

坐席的"数据概览" tab 本来就被 `applyRole()` 隐藏；即使强行点开，看板请求也会被拒并自行隐藏——这一点在浏览器里实测过（见第五节）。

### 3.4 防抖与刷新

登录瞬间会连续触发多次 class 变化，`load()` 内含 1.5 秒节流 + `loading` 互斥，避免同一时刻打四五个请求。

## 四、接口

`cs_admin_dashboard`（管理员口令）

| 入参 | 必填 | 说明 |
| --- | --- | --- |
| `p_code` | 是 | 管理员口令；坐席口令返回 `unauthorized` |
| `p_days` | 否 | 趋势窗口，默认 14，限制 1~90 |
| `p_top_n` | 否 | 知识缺口条数，默认 5，限制 1~20 |

返回：

```json
{
  "ok": true,
  "days": 14,
  "trend_days": 14,
  "wide_days": 30,
  "trend":  { "metric": "ticket_trend", "range": {...}, "columns": [...], "rows": [...], "total": 5, "summary": "..." },
  "intent": { "metric": "intent_share", "rows": [{ "intent": "refund", "label": "退款", "count": 2, "pct": 40 }] },
  "agents": { "metric": "agent_workload", "rows": [{ "agent": "客服A", "claimed": 2, "resolved": 2, "resolve_rate": 100, "avg_first_response": 3600, "rated": 2, "avg_score": 4, "good_rate": 50 }] },
  "gaps":   { "metric": "knowledge_gaps", "rows": [{ "question": "...", "cnt": 1, "intent_label": "其他", "last_seen": "..." }] },
  "generated_at": "...",
  "read_only": true
}
```

限流与分析查询共用同一档（默认 30 次/分钟/操作者）；看板 30 秒刷新一次，远低于阈值。

## 七、取舍

1. **没有做自定义维度/时间选择器**。需求是补四张固定图；开放筛选会让口径解释成本陡增，而真正的自由探索已经由阶段 2 的自然语言查询覆盖。
2. **保留了原来的"近 14 天会话趋势"柱图**。它和新增折线图有重叠，但按要求"不改动原有统计函数与卡片"，两者并存：柱图看总量，折线看三态结构。是否合并留给后续产品决策。
3. **空态优先于补零**。坐席没有接单记录时显示"最近没有坐席接单记录"，而不是渲染一张全 0 的表——0 和"没有数据"是两件事。
4. **图表不写入任何数据**。看板全程只读，和阶段 2 的只读执行器同源。
